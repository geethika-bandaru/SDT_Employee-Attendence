# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-37) | Threshold & floor evaluation bug: evaluates `minutes > 10` after integer division `int((punch_in - start).total_seconds() / 60)`. For 09:40:01, `int(601 / 60) = 10`, and `10 > 10` is False, returning 0 instead of 10. | Punch-in at 09:40:01 for shift 09:30 returns 0 late minutes instead of 10 (violating R2). | Compare raw seconds directly against grace duration: `if diff_sec > 600: return int(diff_sec // 60) else: 0`. |
| 2 | `compute_late_minutes` (lines 34-36) | Timezone mismatch: calls `start = punch_in.replace(hour=h, minute=m)`. If `punch_in` is UTC, replacing hour sets it to UTC instead of IST, producing a negative time difference. | A punch-in at 04:35Z (10:05 IST) calculates start as 09:30Z, resulting in -4 hours 55 min and returning 0 instead of 35. | Convert `punch_in` to IST timezone before calculating the difference with IST shift start. |
| 3 | `compute_work_hours` (lines 40-41) | Uses Python's built-in `round()`, which performs round-to-even (banker's rounding) instead of half-up rounding required by R4 and R8. | Any elapsed duration ending in `.005` or `.025` where even rounding rounds down (e.g. 2.125 rounds to 2.12 instead of 2.13). | Use `Decimal.quantize(..., rounding=ROUND_HALF_UP)`. |
| 4 | `compute_overtime` (lines 44-47) | Missing minimum 30-minute threshold: returns `max(0, int(...))` regardless of whether elapsed minutes reach 30 (violating R3). | Punch-out 25 minutes after shift end returns 25 instead of 0. | Check threshold: `if diff_sec >= 1800: return int(diff_sec // 60) else: 0`. |
| 5 | `compute_overtime` (lines 45-46) | Ignores overnight shifts: sets `end` date to `date_str`. For overnight shifts (`shift_end <= shift_start`), shift end is on the next calendar day. | Overnight shift 22:00 - 06:00 ending on 2026-07-07 sets `end` to 2026-07-06 06:00 (16 hours earlier), generating huge incorrect overtime. | Check if shift is overnight; if so, advance `shift_end` by 1 calendar day from the shift start date. |
| 6 | `EmployeeIn` (lines 53-61) | Missing OpenAPI schema validations (regex patterns, length limits) and does not validate that `shift_start != shift_end`. | Sending invalid `emp_code` format or equal `shift_start` and `shift_end` returns 201 instead of 422. | Added Pydantic field constraints, date validators, and a model validator ensuring `shift_start != shift_end`. |
| 7 | `PunchInIn` (lines 63-67) | Missing timestamp range and type checks; accepts seconds, floats, or invalid status strings like `ABSENT`. | Request with seconds-formatted `punched_at: 1783312500` or invalid status string succeeds instead of returning 422. | Use `StrictInt` with range `100000000000` to `4102444800000` and `PresenceStatusType` literal enum. |
| 8 | `GET /health` (lines 72-74) | Returns static `{"status": "ok"}` without pinging MongoDB, violating readiness probe contract. | When MongoDB is stopped or unreachable, `/health` still returns 200 instead of 503. | Added `client.admin.command("ping")` and return 503 on connection failure. |
| 9 | `POST /employees` (lines 77-85) | Check-then-insert race condition; `created_at` stored as local naive time and returned as ISO string instead of epoch milliseconds. | Concurrent create requests with identical `emp_code` both pass `find_one`; response format violates integer epoch milliseconds schema. | Enforce database unique index on `emp_code`, catch `DuplicateKeyError` to return 409, and serialize `created_at` as epoch milliseconds. |
| 10 | `GET /employees` (lines 88-96) | Pagination offset bug (`skip = page * page_size`), total count ignores department filter, not sorted by `emp_code` ascending. | Page 1 skips the first 20 records; filtering by department reports total count of entire database; order is non-deterministic. | Set `skip = (page - 1) * page_size`, filter `total` with query `q`, and sort cursor by `emp_code` ascending. |
| 11 | `POST /attendance/punch-in` (lines 99-122) | Missing 404 on unknown employee (raises unhandled `TypeError` -> 500); check-then-insert race condition; ignores R1 overnight shift date rules; returns unformatted BSON datetimes and non-schema `"id"`. | Non-existent employee returns 500; overnight punch-in past midnight assigned to wrong day; duplicate punch-ins race; schema violation. | Add 404 check; use unique compound index on `(emp_code, date)` and catch `DuplicateKeyError` returning 409; apply R1 overnight shift calculation; strip internal ID and format epoch ms. |
| 12 | `GET /attendance` (lines 124-150) | In-memory sorting and loading (`list(db.attendance_logs.find(q))`); lacks secondary sort by `emp_code` asc; ignores `date_from > date_to` validation; returns unformatted datetimes. | Memory exhaustion / timeout on 100k records; sorting contract violation; inverted date range returns 200 instead of 422. | Use database cursor sorting `[("date", -1), ("emp_code", 1)]` with `skip()` and `limit()`; validate `date_from <= date_to` with 422; format records properly. |
| 13 | Global (lines 22-23) | Missing startup index initialization; database had no unique or performance indexes. | Sequential collection scans (COLLSCAN) on all queries; duplicate keys allowed under concurrency. | Implemented FastAPI lifespan context manager calling `ensure_indexes()` idempotently on startup. |

### Also examined and decided was NOT a defect:
- **`emp_code` as business identifier:** The starter uses `emp_code` as the primary identifier across endpoints rather than MongoDB's internal `_id`. This is deliberate and strictly aligns with the assignment specifications where `_id` is an internal implementation detail never exposed in the API.
- **Reading `MONGO_URI` and `MONGO_DB` from environment variables:** Reading connection settings from `os.getenv` with sensible localhost defaults ensures compatibility with containerized grading environments and local development without hardcoding credentials.
